I plan to make an extremely light wayland desktop shell project which will have various parts as seen with the directories in this one. I want this colleciton of tools/software made in rust. These tools are meant to be a semi-complete desktop environment on top of niri wm, a smithay based wayland compositor.

The Main process will be a daemon (viledaemon/) that runs on system boot. It will monitor system processes and feed information to and from the other pieces of software within this desktop environment style suite of programs.

The secondary, and most visually complex in the suite is vilebar (vilebar/) This bar will be configurable with a single json file which can configure multiple bars, their position (top/bottom) visual settings, and which monitors each bar in the multi-bar config is placed on. The bar will be a wlr-layer-shell object (preferrably without gtk or qt rendering engines) that will display a single line of text. This single line of text will be fed to the bar by the daemon based on the size of the bar. For example, if the bar is a certain height and width, the bar process calculates the font size relative to the height, and then calculated how many character spaces are available for the daemon to send in order to calibrate how many characters the daemon sends to the bar to display. The bar must also send information to the daemon about where the user's mouse may be hovering over the bar, or where the user is clicking or scrolling during that mouseover. This is so that the daemon can then handle those actions relative to the users system as necessary (such as volume changes, etc) and then determine how to alter that single row of text that is displayed on the bar. The pieces of information displayed on the bar and their positions on the bar will be configurable through the config file which will be in a .config/vile/ directory and accessible by both the daemon and the vilebar pieces of software. Nothing on this bar should be represented by any graphics beyond text characters or unicode icons, things like that. Unlike many overly elaborate wayland shell softwares these days, everything that would have its own widget or popup will be done ON THE BAR. for example, when volume is being adjusted, other elements hide and the bar just becomes a large volume adjustment bar. When the user is adjusting brightness or wants to see battery info, they click those smaller bits of text/areas on the bar and they will transform the bar into a larger version of what the user wants to see, then the bar can change back after (2 seconds by default but configurable) inactivity. Even the app menu/search will take place in the bar with in-line suggestions as the user types (meaning the communication between the bar and the daemon needs to be blazing fast)(notifications will also be displayed on one of these bars if the user wants it there) THE BAR NEVER EXPANDS OR GROWS. IT IS ONLY EVER ONE HORIZONTAL BAR EXACTLY WHERE THE USER CONFIGURES IT TO BE.

(vilecolors/) will be home to what is essentially a vile version of what pywal16 does. It should be compatible with pywal templates, create outputs in its own cache folder (and creates symlinks for the ~/.cache/wal/ directory as well for compatibility with other apps that use pywal16 stuff). it needs to be able to analyze a variety of image file types and extract/analyze their colors in order to create palettes that resemble the stock wal color extraction backend, haishoku backend, and colorz backend. 

(vilewall/) runs independently of vilecolors but will essentially take the place of what something like swaybg does. it will be simpler, and take its instructions from the daemon whether to turn on and display a wallpaper, and how to display it, while the user will talk to the daemon through commands and arguments on those commands. vilewall should be an incredibly light background process that just either displays a wallpaper behind niri or doesnt.

(vilesettings/) likely to be developed last, is a settings menu that handles various vile software settings as well as niri configurations.
